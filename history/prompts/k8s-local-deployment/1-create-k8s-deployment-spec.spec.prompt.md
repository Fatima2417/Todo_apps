## Prompt

**Project Phase:** Phase 4 - Local Kubernetes Deployment of Todo Chatbot **Target Audience:** Hackathon evaluators, developers interested in AI-assisted DevOps, and practitioners learning Kubernetes deployment with AI tools. **Focus:** Containerizing the existing Todo chatbot (frontend + backend) and deploying it on a local Minikube cluster using AI‑assisted tools: - **Gordon** (Docker AI) for Dockerfile generation and image builds - **kubectl-ai** and **kagent** for creating Helm charts and managing Kubernetes resources - **Helm** for packaging and deploying the application The emphasis is on leveraging AI to generate correct infrastructure code, not writing it manually. **Success Criteria:** 1. **Containerization** - Dockerfiles for both Next.js frontend and FastAPI backend exist and are generated by Gordon (or Claude Code following Gordon's suggestions). - Docker images are built successfully and tagged appropriately. - Images run locally and expose the same functionality as Phase III. 2. **Helm Charts** - Helm charts are created for frontend and backend (either separate charts or one umbrella chart). - Charts include: - Deployments with resource requests/limits - Services (ClusterIP for internal, NodePort for frontend access) - ConfigMaps for environment variables (excluding secrets) - Secrets for API keys (Cohere, etc.) stored securely - Charts are parameterised via `values.yaml` and can be installed with a single `helm install` command. 3. **Kubernetes Deployment** - Minikube cluster is running (with Docker driver). - `helm install` completes without errors. - All pods are in `Running` state. - Application is accessible from the host (e.g., via `minikube service frontend` or port‑forward). - The chatbot functionality (Phase III) works inside the cluster (connects to Neon database, processes natural language). 4. **AI Tool Usage** - Gordon was used for Dockerfile creation and/or image builds. - kubectl-ai was used to generate at least one Kubernetes manifest or to assist with debugging. - kagent was used to analyse cluster health or suggest optimisations. - All AI tool commands and their outputs are documented in the repository (e.g., in a `docs/phase4-ai-log.md`). 5. **Reproducibility** - The entire deployment can be destroyed (`helm uninstall`) and recreated from scratch using only the specs and the provided scripts. - No manual edits to YAML files are required after AI generation. **Constraints:** - **Environment:** Must run on Minikube v1.38+ with Docker driver on the user's local machine (as verified in the setup). - **Resources:** Must respect the Minikube VM’s memory (≤4GB) and CPU (≤4 cores) limits to avoid instability. - **No Manual Code Edits:** All Dockerfiles, Helm charts, and Kubernetes YAML must be generated by Claude Code from specifications; any manual tweaks must be reflected back in the specs. - **Fallback for Gordon:** If Gordon is unavailable in the user's region/tier, standard Docker CLI commands may be used, but this must be documented, and the rationale recorded. - **External Dependencies:** The application still relies on the Neon PostgreSQL database (cloud) and Cohere API – network connectivity from the cluster to these services must work. - **Version Control:** All generated artifacts (Dockerfiles, Helm charts, Kubernetes YAMLs) must be committed to the GitHub repository. **Not Building:** - No new application features – Phase III functionality remains unchanged. - No cloud deployment (Azure, GKE, DOKS) – that is Phase V. - No production-grade concerns (HA, auto‑scaling, monitoring, logging) – these may be introduced in Phase V. - No persistent storage for the database – the database remains external (Neon). - No service mesh or advanced networking. **Deliverables:** 1. **Dockerfiles** - `Dockerfile.frontend` and `Dockerfile.backend` (or equivalent) in the repository root. - `.dockerignore` files to keep images slim. 2. **Helm Charts** - `helm/todo-frontend/` and `helm/todo-backend/` directories (or a single chart) with all templates and `values.yaml`. - `Chart.yaml` and `values.yaml` properly configured. 3. **Kubernetes Manifests (optional)** - If Helm is not used for some resources, plain YAMLs may exist, but Helm is preferred. 4. **Documentation** - Updated `README.md` with Phase 4 instructions: - How to build images with Gordon (or Docker). - How to install Helm charts. - How to access the application. - How to tear down. - `docs/phase4-ai-log.md` containing all AI tool commands and outputs. 5. **Verification Script** (optional) - A script that runs `helm install`, waits for pods, and tests a simple chat command to confirm functionality. **Acceptance Tests:** - [ ] Run `minikube status` – cluster is running. - [ ] Build images with Gordon (or Docker) – success. - [ ] `helm install todo-release ./helm` – success. - [ ] `kubectl get pods` – all pods `Running`. - [ ] `minikube service frontend` – opens browser with the Todo app, chat widget works. - [ ] Send a test message ("Add task via Kubernetes") – task is created in database, response confirms. - [ ] `helm uninstall todo-release` – all resources removed. - [ ] Reinstall using the same commands – still works. - [ ] AI tool usage is documented and consistent with the spec.
